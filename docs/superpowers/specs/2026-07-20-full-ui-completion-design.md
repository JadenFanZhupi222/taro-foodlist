# 家庭食谱小程序全页面 UI 完成设计

## 目标

在不改变现有业务能力、数据结构、Redux 流程、云函数和路由的前提下，将剩余页面和全局状态统一为完整的现代家庭食谱体验。微信小程序是首要运行环境，H5 仅用于快速预览与视觉校验。

## 设计判断

这是面向家庭成员的生活型工具，不是外卖、餐饮商城或内容平台。界面采用温暖、克制、可信的现代 iOS 家庭工具语言：暖白背景、墨绿色信息层级、陶土橙主操作和低饱和辅助色。

- 设计变化度：6/10
- 动效强度：7/10
- 信息密度：4/10
- 视觉原则：统一温度，不复制模板

## 范围

### 包含

- 食谱详情页与食谱新建/编辑页
- 今日菜单及添加菜谱页的视觉收口
- 家庭主页、无家庭状态、成员列表和邀请页
- 个人主页与个人资料编辑页
- 收藏、历史、通知、隐私和关于页面
- 全局标题、卡片、按钮、表单、加载、空状态、错误状态和安全区
- 页面进入、列表出现、按钮按压、选择、展开和删除反馈

### 不包含

- 新增收藏、历史、通知等业务能力
- 修改数据库、云函数或线上数据
- 修改 Redux state、thunk、selector 或 API 契约
- 修改页面路由和微信项目配置
- 修改用户当前未提交的 `project.config.json`

## 页面架构

### 食谱流程

食谱库继续采用双列卡片。详情页以大图封面、菜谱说明、食材和步骤为主，强化家庭记录感。编辑页采用分段表单，将基础信息、食材清单和步骤拆开，保持现有提交与编辑逻辑。

### 今日流程

今日菜单突出日期、用餐计划和当前选择。添加菜谱页强化搜索、分类和选中反馈，不改变原有选择、保存和移除行为。

### 家庭流程

家庭主页以成员和共享状态为核心。家庭摘要使用深色关系卡，成员使用清晰的头像、姓名和角色结构。邀请页采用轻量欢迎卡和明确操作，不使用营销页或平台式语言。

### 个人流程

个人主页是设置入口。资料编辑使用分组表单。收藏、历史、通知、隐私和关于页面不再共用通用“敬请期待”，而是显示与各自页面语义匹配的完整说明、当前状态和可用入口，但不产生新的数据能力。

## 视觉系统

### 色彩

- 页面背景：暖白灰 `#F7F7F4`
- 卡片背景：白色或轻暖灰
- 主文字：墨黑绿 `#20241F`
- 次文字：低饱和灰绿
- 主操作：陶土橙
- 成功与家庭关系状态：柔和苔藓绿
- 危险操作：只在删除确认和破坏性动作中使用

所有颜色优先通过 `src/use/variables.scss` 的语义 token 使用，页面不得复制一套新的近似色系统。

### 排版

- 页面标题清晰但不夸张，保持 iPhone 小屏可读性
- 辅助标签使用较小字号和正常中文，不做大面积全大写或过宽字距
- 表单标签、正文、辅助说明和按钮形成稳定层级
- 页面文字使用真实家庭语境，避免促销、下单、爆款等外卖平台措辞

### 圆角与阴影

- 按钮与小控件使用中等圆角
- 主要卡片使用较大圆角
- 弹层使用最大圆角
- 阴影只用于需要层级分离的浮层、封面或底部操作，不给所有卡片加重阴影

### 图像

现有菜谱图片继续作为核心内容。没有图片时使用统一的家庭餐盘或食材占位视觉，不伪造远程内容，也不修改图片存储逻辑。

## 组件边界

- 页面容器：负责安全区、背景、标题和底部导航留白
- 页面标题：支持 eyebrow、标题、说明和右侧操作
- 卡片：食谱卡、家庭摘要卡、成员卡和设置分组各自保留语义，不强行合并为一个万能卡片
- 表单：统一标签、输入区、错误提示、帮助文字和分段间距
- 状态视图：按加载、空、错误三类提供统一结构，页面传入具体文案和操作
- 操作反馈：主按钮、次按钮、文字按钮和危险按钮使用固定层级

组件只接受展示数据和回调，不读取新的业务状态，不新增数据写入。

## 动效规范

- 页面进入：轻微上移加透明度过渡
- 列表和卡片：短间隔顺序出现，避免长时间阻塞操作
- 按钮：按压缩放与颜色反馈
- 选择状态：背景、描边和内容同步变化
- 展开与删除：保持状态变化连续，不做突然跳变
- 加载：延续家庭餐盘意象，不使用平台式促销动画

不减少现有动画强度。禁止无意义循环漂浮、自动轮播和影响操作的装饰动画。微信端不使用会在编译时留下空规则的通配符媒体查询。

## 状态与错误处理

- 加载：保留当前业务加载条件，仅替换呈现
- 空状态：每页使用与业务场景匹配的标题、说明和现有操作
- 错误状态：在页面内保留说明与现有重试回调；Toast 只作为辅助反馈
- 占位页面：收藏、历史、通知、隐私和关于页面显示稳定完成态，不声称尚未实现的业务已经可用
- 删除和退出：保持原确认逻辑，视觉上明确危险性

## 微信端兼容边界

- 微信小程序产物是完成标准
- 避免 WXSS 不支持的选择器和媒体查询组合
- 避免依赖动态创建浏览器组件的核心交互
- 样式修改后检查生成的 `.wxss`，防止空媒体块和非法 token
- 不把 H5 专用能力当作微信端依赖

## 验证

每批改造执行：

1. 与页面结构或样式约束对应的回归测试先失败、后通过
2. `pnpm build:weapp`
3. 检查生成 WXSS 和关键页面 JS 中没有已知非法结构
4. 核心页面使用 iPhone 尺寸进行视觉检查
5. 验证加载、空、错误和正常数据状态
6. 确认 `project.config.json`、数据库、云函数和业务状态代码未被意外修改

## 完成标准

- 所有已注册页面都有与其语义匹配的完整界面
- 不再出现通用“敬请期待”页面
- 四条核心流程视觉一致但页面编排不重复
- 页面在微信开发者工具中可编译、可打开
- 原有业务行为和数据调用保持不变
- 动效、触控反馈和安全区在 iPhone 尺寸下完整
