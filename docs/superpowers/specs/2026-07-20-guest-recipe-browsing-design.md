# 游客食谱浏览设计

## 目标

微信审核员在不登录、不授权头像昵称或手机号的前提下，可以从食谱首页浏览体验食谱并进入详情查看食材和步骤。新增、编辑、删除、家庭共享和菜单操作仍要求登录。

## 方案

移除 `AppContainer` 的全局登录弹窗。未登录时，食谱首页使用随包发布的只读体验食谱；登录后只展示用户家庭的云端食谱，体验数据不会写入 Redux、云数据库或登录用户列表。详情页按相同规则解析体验食谱。

首页明确标注“游客体验”，并提供主动登录入口。游客卡片不启用滑动删除；点击新建或登录入口时才跳转个人页完成登录。其他标签页保持原有鉴权边界。

## 数据与边界

- 体验食谱存放在独立、可测试的本地模块中，使用保留前缀的稳定 ID。
- 体验数据仅含菜名、分类、说明、食材和步骤，不含用户或家庭数据。
- 登录状态以现有 `selectUser` 为准；登录后不混入体验数据。
- 详情页只有登录用户的真实食谱显示编辑按钮。

## 错误处理

未知体验 ID 和已删除真实食谱继续显示现有“没有找到”状态。游客下拉刷新只结束刷新动画，不调用受保护云函数。

## 验证

新增 Node 测试验证体验数据、可见食谱选择和按 ID 查找；源码回归测试验证全局弹窗被移除、游客卡片不可删除、写操作跳登录。最后运行 UI 测试、TypeScript/微信构建和完整后端测试。
