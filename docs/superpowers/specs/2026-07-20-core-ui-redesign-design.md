# 核心三页 UI 重设计

## 范围

改造食谱库、今日食谱、我的三个 Tab 页面及全局底部导航。保留 Redux、云函数、数据结构、登录和页面跳转逻辑，不重构后端。

## 体验目标

- 家庭成员能快速找到已有食谱并新建食谱。
- 当日菜单在一屏内完成查看、切换日期、加菜与移除。
- 个人页清楚呈现账户、家庭入口、收藏、历史和设置。
- 所有页面使用同一设计令牌、组件语言和 iPhone 安全区策略。

## 视觉系统

以 [DESIGN.md](../../../DESIGN.md) 为唯一视觉规范。页面采用中性雾白背景、深橄榄文字和克制陶土红强调；真实菜品图片承担温度。禁止外卖平台式促销视觉、儿童卡通化和奶油色卡片堆叠。

## 页面设计

### 食谱库

顶部为页面标题、家庭食谱数量和新增入口，其下为搜索框与横向分类。内容使用响应式双列图片卡；空结果提供清除筛选或新建食谱的行动。删除保留滑动操作，卡片本身不出现孤立 `x`。

### 今日食谱

顶部为标题和日期切换；摘要区域表达当天菜品数量及荤素汤搭配；菜单改为纵向横卡，图片、菜名、分类和移除动作同时可见。底部主按钮打开现有加菜面板，过去日期不显示编辑操作。

### 我的

顶部用户区突出家庭身份；登录后展示家庭、收藏和历史入口，未登录时提供清晰登录说明。功能和设置使用扁平分组列表，不依赖大阴影卡片。

### 自定义导航

使用 Taro React 自定义 TabBar。三个入口保持“食谱 / 今日 / 我的”，当前项通过陶土红、字重和图形共同表达。导航包含 `env(safe-area-inset-bottom)`，页面内容预留对应底部空间。

## 动效与状态

- 按钮、筛选和导航状态：180ms ease-out。
- 日期和列表内容切换：240ms ease-out。
- 加载优先使用骨架结构；现有全屏 Loading 仅保留冷启动兜底。
- 默认保留完整状态动效；系统开启减少动态效果时取消位移和缩放，仅保留淡入淡出。

## 验收

- 微信小程序生产构建通过。
- 三个 Tab 可切换且激活态正确。
- 原有搜索、筛选、详情跳转、添加、删除、日期切换、登录和设置入口保持可用。
- 375–430px 宽度无横向溢出，底部操作不与 iPhone Home Indicator 冲突。
- 正文不小于 14px，关键文字与背景达到 WCAG AA 对比度。
