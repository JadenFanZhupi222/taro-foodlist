# UI 韧性加固设计

## 目标

修复空数据、短内容、长文本和请求失败时的误导或破版行为。已有数据模型和业务规则保持不变：食材、步骤、描述仍可为空，写操作仍遵循现有登录与家庭权限。

## 设计原则

1. **未知不等于空。** 请求失败、关联数据尚未加载和服务端确认空数据必须分别展示。
2. **失败不报成功。** 所有写操作只有在异步 thunk fulfilled 后才提示成功并离开页面。
3. **空内容可理解。** 空分区显示紧凑说明，不留下裸标题；编辑空数组时至少提供一行输入。
4. **固定操作不遮内容。** 页面为固定底栏和安全区保留空间，网格以容器宽度而非 viewport 宽度计算。
5. **不可信文本可换行。** 用户输入的名称、数量和值允许收缩和断词，不能挤压相邻元素。

## 食谱

- 详情页为空的食材和步骤分别显示“暂未填写食材/步骤”。
- 编辑旧数据中的空数组时初始化一行空食材和一步空步骤。
- 保存使用 thunk `.unwrap()`；失败停留当前页并提示重试，更新不再先污染 Redux。
- 已登录用户从详情深链/冷启动进入时，缺少本地数据会按 ID 拉取；加载、失败、确定不存在分别展示。
- 描述/步骤输入框使用 border-box；长菜名、食材和数量可以换行且不碰撞分类标签。

## 今日菜单

- 没有登录用户或家庭时不允许进入添加流程，也不向云函数发送空 ID；提供去登录/建立家庭的明确动作。
- 按日期请求失败时显示错误和重试，不进入永久转圈。
- 菜单含 recipe_id 但食谱尚未加载时显示解析中，不误报空菜单。
- 添加菜谱浮层使用容器网格，空状态占满网格，不使用 `vw` 撑破浮层。

## 家庭与邀请

- 家庭请求失败保留已有家庭数据，并显示可重试错误；只有成功返回 null 才展示“尚未加入家庭”。
- 邀请缺少 ID、加载失败或家庭不存在时显示错误状态，未拿到真实家庭前禁用接受按钮。
- 空成员列表使用居中的紧凑空状态。

## 通用边界

- 用户和成员头像为空时回退到默认头像。
- 设置页长 value 限宽、右对齐并允许断词。

## 测试与发布

以 Node 行为/源码回归测试覆盖状态选择、异步失败和布局约束；所有修复遵循 RED-GREEN。最后运行 UI、后端测试和微信构建，独立代码审查无阻断问题后通过 PR 合入并监控体验版上传。
