# 菜谱详情图片放大交互设计

## 目标

让用户在菜谱详情页点击头图后，可以自然地进入全屏查看，并使用平台原生的缩放与拖动能力观察菜品细节。

本次只处理菜谱详情页的单张头图，不扩展为图片画廊，也不改变图片上传、存储或详情数据结构。

## 交互方案

采用“轻触反馈 + 原生全屏预览”的组合：

1. 有图片时，整张头图是可点击区域。
2. 用户按下头图时，图片在约 160ms 内缩小至 `0.985`，松开后恢复，提供克制的触感反馈。
3. 点击事件调用 `Taro.previewImage`，将当前菜谱图片同时作为 `current` 和唯一的 `urls` 项。
4. 全屏预览中的进入、退出、双指缩放与拖动由当前运行平台提供。
5. 头图右下角显示半透明的“放大查看”提示，明确图片可交互。提示不遮挡主体，不单独响应点击。
6. 菜谱没有图片时继续显示现有餐盘占位图，不显示提示，也不触发预览。

## 视觉与动效

- 头图原有尺寸、裁切模式和详情内容叠接关系保持不变。
- “放大查看”提示使用半透明深色底、白色小号文字和紧凑圆角，保持现有中性、克制的视觉语言。
- 按压动画只使用 `transform`，避免布局重排。
- 默认过渡时长为现有快速动效变量 `$duration-fast`，缓动使用 `$ease-out`。
- 在支持 `prefers-reduced-motion: reduce` 的环境中取消额外过渡，避免强制动态效果。

## 实现边界

在 `src/pages/recipe/detail/index.tsx` 中：

- 为有图片的头图增加可点击容器。
- 新增局部预览处理函数，调用 `Taro.previewImage`。
- 提示文本使用现有 Taro `View`、`Image`、`Text` 组件完成，不引入新依赖。

在 `src/pages/recipe/detail/index.scss` 中：

- 增加头图容器、按压状态与提示样式。
- 保持现有占位图样式与内容入场动画不变。

不增加全局状态，不新增通用组件；当前只有一个调用点，局部实现更容易理解且不会扩大公共 API。

## 异常处理

- `Taro.previewImage` 失败时不阻塞页面，也不改变当前图片状态。
- 失败后通过现有轻量提示能力告知用户“图片暂时无法预览”，避免静默无反馈。
- 仅在 `recipe.image` 为非空值时注册预览行为，从源头避免无效调用。
