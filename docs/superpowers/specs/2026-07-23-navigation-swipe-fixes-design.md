# 导航与滑动删除修复设计

## 目标

修复食谱卡片左滑卡顿和删除区高度不足、“我的”图标空白、底部导航遮挡日期选择器确认按钮三个问题，同时将底部导航与滑动删除统一重设计为更稳定的移动端交互。

## 范围

保留“食谱 / 今日 / 我的”三个入口、路由顺序、删除接口和二次确认逻辑。只调整自定义底部导航、食谱卡片滑动交互及相关样式与测试，不改后端数据结构或云函数。

## 底部导航

- 采用已确认的 B 方案：低矮、贴近安全区底部的悬浮胶囊。
- 导航始终固定可见，不随滚动隐藏，保持三个核心入口随时可达。
- 将 `cover-view` 全部替换为普通 `view`。导航不再作为原生覆盖层，因此系统日期选择器能自然显示在导航上方，无需打开选择器时临时隐藏导航。
- 胶囊外部壳层不拦截页面点击，只有胶囊本身响应切换操作。
- “我的”图标及其他图标使用真实子元素绘制，不依赖 `cover-view` 伪元素；统一描边粗细和选中态颜色。
- 页面底部继续预留导航与安全区空间，避免正文和操作按钮被胶囊覆盖。

## 滑动删除

- 重做卡片横向手势，动画只修改 `transform`，避免卡片按压态与滑动位移争用同一属性。
- 手势开始后先判断方向：纵向意图优先保持页面滚动；只有横向位移明显占优时才锁定为左滑操作。
- 删除按钮是独立圆角操作块，与当前卡片完整等高，并使用明确文字“删除”。
- 同一时间只允许一个卡片展开；开始滑动另一张卡片或点击页面其他区域时，已展开项自动收起。
- 删除区展开时，首次点击卡片本体只收起，不进入详情；收起后再次点击才进入详情。
- 无论左滑距离多长，松手都只展开删除按钮，不直接执行删除。
- 点击删除按钮后继续显示现有二次确认；确认后调用现有删除流程，取消后收起当前卡片。
- 游客卡片继续禁用滑动删除。

## 状态与失败处理

- 卡片只维护关闭、拖动和展开三类可见状态；父级协调当前展开的卡片 ID。
- 删除请求沿用现有成功与失败提示。请求失败时不移除本地菜谱，滑动状态恢复为关闭，用户可以重试。
- 日期选择器沿用系统确认与取消行为，导航无需监听或切换可见性。

## 验证

- 源码回归测试验证自定义导航不再使用 `cover-view`，图标包含真实绘制元素，且胶囊采用受控层级与贴底布局。
- 组件/源码测试验证滑动只展开操作区、一次只展开一个、卡片展开时点击先收起，以及游客不可滑动。
- 样式测试验证删除操作区与卡片等高，滑动动画只使用 `transform`，卡片按压态不与其冲突。
- 运行 UI 测试、TypeScript 检查和微信小程序构建；在微信开发者工具中手动确认日期选择器的确认与取消按钮均可点击。

## 非目标

- 不新增导航入口，不调整页面路由。
- 不允许完整左滑直接删除。
- 不替换系统日期选择器。
- 不修改云函数或数据库删除语义。
